# Power Automate — потоки портала

## Оформить покупку награды (`d4142c4e-38a5-f111-b8de-000d3adcd7a2`)

Триггер «When Power Pages calls a flow», вход `rewardItemId` (ключ `text`), выходы
`ok / message / balance / stock`. Вызывается из Rewards-Shop через
`/_api/cloudflow/v1.0/trigger/<guid>` (form-urlencoded, поле `eventData`).

`Оформить-покупку-награды.flow.json` — эталонное определение (из экспорта решения
LMSfarovon после правки 2026-08-31). Если поток править в конструкторе — после сохранения
экспортировать решение заново и обновить файл, иначе репозиторий соврёт.

`fix-flow.js` — скрипт, которым определение чинили: пустая схема триггера, вложенные циклы,
пробелы в лукапах, пустой остаток, типы выходов. Пригодится как образец, если придётся
править определение снова: экспорт → распаковать в C:\tmp\flow-src → node fix-flow.js →
Compress-Archive → импорт решения.

`stock = -1` в ответе = награда без лимита (пустой `new_stock`).

## Проверка покупки награды (`aa00b5f1-64a0-4b5f-9c00-20260831b50f`) — действующая схема

Портальный endpoint `/_api/cloudflow` на этом сайте неисправен (сайт мигрирован со старого
шаблона ProgramRegistration_V2; проверено 2026-08-31: лицензия, привязка, оба формата тела,
Clear config, перезапуск — всегда 500 без запуска). Поэтому контроль покупок перенесён
на Dataverse-триггер:

- магазин пишет покупку напрямую (`POST /_api/new_rewardpurchases`), как раньше;
- поток срабатывает «при создании записи» (от владельца), сверяет цену со справочником
  (расхождение исправляет), пересчитывает баланс по формуле экранов; запись, уводящую
  баланс в минус, или по неактивной/закончившейся награде — удаляет; честной покупке
  списывает `new_stock` (пустой остаток = без лимита, не трогается).

Поток «Оформить покупку награды» оставлен выключенным — вернуться к синхронной схеме
можно только после починки cloudflow на стороне Microsoft, проверив на этом же сайте.
