**Техническое задание на разработку платформы для автоматизации процесса адаптации**



**Цель проекта**



Создание комплексной платформы для автоматизации процесса адаптации персонала новых сотрудников в компании.



Платформа состоит из двух частей:



- **Веб-сайт (CMS) -** используется администратором сайта и сотрудниками компаний для наставничество, отслеживания процесса адаптации новичка, коммуникации, постановка задач, добавления/изменения материалов обучения и тестов.

- **Веб-сайт и мобильная приложения (пользовательский)** - используется пользователями (новыми сотрудниками) для ознакомления с компанией и с профессией, выполнении задач и коммуникации с наставником.



Ролевые модели и их действия



Платформа имеет 5 ролевых моделей:



- **Администратор** - управления пользователями, регистрация пользователей, определения уровня доступа пользователям, размещения/удаления/изменения любых материалов.

- **HR** - регистрация пользователей, изменения своего профиля (фото, номер телефона, email, пароль), размещения/удаления/изменения материалов которых он добавил, наблюдения и постановка задач тем адаптациям/стажировкам в которых он менеджер процесса, создания тестов и опросов, общая отчетность по подразделениям в которых он ответственный.

- **Наставник** - наблюдения и постановка/удаления/изменения задач тем адаптациям/стажировкам в которых он наставник, изменения своего профиля (фото, номер телефона, email, пароль), оценка стажеров + итоговая оценка после прохождения стажировки/адаптации, отчетность по стажировкам/адаптациям в которых он наставник.

- **Руководитель** - изменения своего профиля (фото, номер телефона, email, пароль) наблюдения за процессом адаптации в которых он руководитель, изменения своего профиля (фото, номер телефона, email, пароль) отчетность по стажерам и наставникам. **Также он сам может стать наставником**. Наблюдения и постановка/удаления/изменения задач тем адаптациям/стажировкам в которых он наставник, оценка стажеров + итоговая оценка после прохождения стажировки/адаптации, отчетность по стажировкам/адаптациям в которых он наставник.

- **Пользователь (Новый сотрудник)** - обучения, выполнения задач, отчетность по пройденных материалов и выполненных задач, отслеживания своей эффективности, изменения своего профиля (фото, номер телефона, email, пароль), оценка наставника, прохождения опросов и тестов.



Требования для разработки веб-сайта (CMS)



Необходимо разработать веб-сайт для работы с платформой следующим ролям пользователей: администратор, HR, руководитель, наставник. Веб-сайт должен иметь единый стиль элементов для всех страниц.



Для входа в систему все пользователи будут использовать единую страницу входа. После авторизации система учитывая роль пользователя предоставляет доступ к необходимым страницам.

- Раздел "Активные"



- Отображение списка текущих, незавершенных задач пользователя

- Для каждой задачи отображение: название, описание, постановщик, срок выполнения, комментарии, статус, кнопка "Завершить"

- Возможность прикрепления файлов к задаче

- Поле для ввода результата выполнения задачи



- Раздел "Выполненные"



- Отображение списка ранее выполненных задач пользователя

- Для каждой задачи отображение: название, описание, постановщик, срок выполнения, комментарии, статус, оценка



Требования к функционалу:



- При назначении новой задачи пользователю, ему должно приходить уведомление о ее появлении.

- После завершения задачи пользователем, ему должно приходить уведомление о принятии/оценке задачи.

- Статусы задач должны автоматически обновляться в зависимости от действий пользователя: "В процессе", "Ждет проверки", "Выполнено", "Отменено", "Не начато".

- Пользователь должен иметь возможность отмечать задачу как "Начатую" через специальную кнопку.

- Наставник должен иметь возможность просматривать все задачи пользователей, оценивать их и комментировать.

- Вся информация о задачах (название, описание, статус, комментарии и т.д.) должна храниться в базе данных.



Дополнительные требования:



- Интерфейс страницы должен быть интуитивно понятным и удобным для пользователя.

- Должна быть предусмотрена возможность фильтрации и сортировки задач по различным параметрам (статус, срок, постановщик и т.д.).

- При прикреплении файлов к задаче должен быть предусмотрен подходящий механизм загрузки.

Дополнительные требования:



\- Интерфейс страницы должен быть интуитивно понятным и удобным для пользователя.



\- Должна быть предусмотрена возможность фильтрации и сортировки мероприятий по различным параметрам (дате, формату, статусу участия и т.д.).

\- Постановщик мероприятии должен иметь возможность добавлять, редактировать и удалять мероприятия через специальный интерфейс управления.
