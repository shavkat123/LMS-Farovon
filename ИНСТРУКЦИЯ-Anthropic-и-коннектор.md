# Подключаем Claude к Power Automate: пошаговая инструкция для владельца

**Что получится в итоге.** У платформы появится оплаченный доступ к модели Claude по API и «подключение» в Power Platform, через которое потоки ИИ-экзаменатора смогут вызывать модель. Ключ при этом будет храниться внутри Power Platform, а не в коде и не в переписке.

**Сколько это занимает.** Часть 1 (Anthropic) — примерно 30–40 минут, если платёжная карта под рукой. Часть 2 (Power Platform) — 10–15 минут плюс пауза в несколько минут перед проверкой.

**Что нужно заранее:**
- рабочая почта, на которую заводится организация Anthropic;
- платёжная карта (оплата предоплаченными кредитами);
- доступ к Power Platform с лицензией Premium — под учётной записью, которой будут принадлежать потоки экзамена (в методичке это отдельная сервисная учётка, не ваша личная);
- права администратора Power Platform, если в тенанте настроена политика DLP.

**Про названия кнопок.** Интерфейсы Anthropic и Microsoft меняются. Там, где точная надпись на кнопке не подтверждена документацией, я пишу «пункт называется примерно так» — ищите по смыслу, а не по буквам. Там, где надпись подтверждена, она приведена дословно (иногда по-английски — интерфейс консоли Anthropic англоязычный).

## Часть 1. Учётная запись Anthropic и ключ API

### Шаг 1. Откройте консоль

Откройте в браузере **platform.claude.com**.

Старый адрес `console.anthropic.com` тоже рабочий — он автоматически перебрасывает на `platform.claude.com` (проверено). Документация — `platform.claude.com/docs/`, поддержка — `support.claude.com`. Сам продукт в документации называется **Claude Console**.

*Как понять, что получилось:* вы видите страницу входа или, после входа, консоль с левым меню (Usage, Cost, Settings и т. д.).

> **Не перепутайте:** `claude.ai` — это чат-продукт с подпиской, он к API отношения не имеет. Подписка Pro/Max на claude.ai **не даёт** ни ключа, ни кредитов для API. Это отдельная услуга с отдельной оплатой.

### Шаг 2. Войдите или создайте аккаунт

Документация описывает этот шаг ровно одной фразой: «Go to platform.claude.com and sign in, or create an account if you don't have one yet.»

Дальнейший порядок регистрации (почта и пароль, вход через корпоративную учётку, подтверждение телефона) в документации **не описан** — идите по экранам, которые вам покажут. Что именно вы увидите, я подтвердить не могу.

*Как понять, что получилось:* вы внутри консоли и видите левое меню.

### Шаг 3. Настройте организацию

Индивидуальный аккаунт и организация — **не одно и то же**. Организация настраивается отдельно: **Settings → Organization** (по документации; точные названия полей на этом экране не подтверждены).

Там же при первом запуске от вас попросят сведения об организации, сценарий использования и платёжные данные — это отдельный шаг, а не часть регистрации.

Зачем это нужно: без организации нельзя добавлять коллег, а служебный Admin API (им пользуются для выгрузки расходов) для индивидуальных аккаунтов недоступен.

*Как понять, что получилось:* в Settings появились разделы, относящиеся к организации (участники, workspaces, биллинг).

### Шаг 4. Проверьте свою роль

В консоли шесть ролей: **User, Claude Code User, Limited Developer, Developer, Billing, Admin**.

Что вам понадобится:
- **создавать ключи** — Limited Developer, Developer или Admin;
- **покупать кредиты и менять лимиты расходов** — Billing или Admin;
- **создавать workspace (рабочие пространства)** — только Admin (дословно: «Only organization admins can create workspaces»);
- **смотреть расходы** — Limited Developer, Developer, Billing, Admin.

Если вы создавали организацию сами — вы Admin, и всё доступно.

*Как понять, что получилось:* на странице ключей кнопка **Create key** активна. Если она серая — это почти всегда про роль; документация прямо предупреждает: «If the Create key button on the API keys page is disabled, your role may not allow you to create keys there.»

### Шаг 5. Купите кредиты

API оплачивается **предоплаченными кредитами**: «Claude API and playground usage is billed through prepaid usage credits».

1. **Settings → Billing**.
2. Нажмите **Buy credits**.
3. Укажите сумму и оплатите.

Кредиты зачисляются сразу. Списывается оплата только за успешные вызовы: «You're billed only for successful API calls and completed tasks.»

**Начните с небольшой суммы.** Причины две, обе из документации: «Credits expire one year from the purchase date, and the expiration date can't be extended» (кредиты сгорают через год) и «All credit purchases are non-refundable» (возврата нет). Для запуска и смоук-теста достаточно минимального пополнения; докупить можно в любой момент за минуту.

*Как понять, что получилось:* на странице Billing виден ненулевой баланс кредитов.

> Существует и вариант постоплаты (счёт раз в месяц, счета приходит из Stripe), но он оформляется через отдел продаж Anthropic — это не кнопка в интерфейсе. Для старта не нужен.

### Шаг 6. Создайте отдельный workspace (рекомендуется, требует роли Admin)

Workspace — это «отсек» внутри вашей организации: отдельный учёт расходов, отдельные лимиты, изоляция ключей.

**Зачем это делать именно вам:** поставить лимит расходов **на Default Workspace нельзя** («You cannot set limits on the Default Workspace»). Если вы хотите отсечённый бюджет под экзамен — нужен свой workspace.

1. **Settings → Workspaces**.
2. Кнопка **Create workspace**.
3. Задайте имя (например, `LMS Exam`) и цвет → **Create**.

*Как понять, что получилось:* workspace появился в списке, у него есть вкладки с лимитами.

> **Осторожно:** архивирование workspace необратимо и архивирует все его ключи. Отдельно: архивирование workspace «Claude Code», если он есть, отключает вход в Claude Code через биллинг консоли для всей организации. Просто не трогайте архивирование.

### Шаг 7. Создайте ключ API

1. **Settings → API keys** (прямая ссылка: `platform.claude.com/settings/keys`).
2. Нажмите **Create key**.
3. Заполните (дословно из документации: «name the key, choose an expiration, and set Linked account to yourself or a service account. You can also choose a workspace to scope the key to»):
   - **Имя** — понятное, например `LMS Exam — Power Automate`.
   - **Expiration (срок действия)** — см. предупреждение ниже.
   - **Linked account** — по возможности **service account**, а не вы лично. Личный ключ перестаёт работать, когда человек выходит из организации, — экзамен встанет. Если создать service account не получается (может упираться в роль), возьмите личный, но запишите это как риск.
   - **Workspace** — **обязательно выберите тот workspace, который создали в шаге 6**.

**Почему workspace здесь критичен.** Ключ, не привязанный к одному workspace, требует в каждом запросе дополнительный заголовок `anthropic-workspace-id`, иначе API отвечает ошибкой 400 с текстом «anthropic-workspace-id is required when authenticating with an identity-linked API key». Наш коннектор этот заголовок **не посылает**. Ключ, созданный «в» конкретный workspace, заголовок не требует и работает сразу.

**Про срок действия — решайте сейчас, потом не изменить.** Дословно: «expiration is set at creation time and cannot be changed afterward». Варианты: 3 часа / 1 день / 7 дней / 30 дней, произвольный срок или **Never**. Когда срок истечёт, экзамен просто начнёт получать 401 без предупреждения. Практичный подход: если методичка предписывает ротацию раз в 90 дней — поставьте 90 дней и **сразу же** поставьте себе напоминание в календаре на 80-й день. Если такой дисциплины не будет — честнее выбрать **Never** и ротировать вручную, чем получить внезапную остановку экзамена.

*Как понять, что получилось:* появилось окно с полным ключом.

### Шаг 8. Скопируйте ключ немедленно

Дословно: «The Console shows the full key, which starts with `sk-ant-`, only once, at creation. Copy it and store it somewhere safe, such as a secrets manager. If you lose a key, you can't view it again in the Console. Create a new key instead.»

- Нажмите «копировать» и **сразу** вставьте ключ в менеджер паролей (или в другое защищённое хранилище, которым вы пользуетесь).
- Не закрывайте окно, пока не убедились, что ключ сохранён.
- Потерянный ключ не восстанавливается **никак** — даже служебный Admin API отдаёт только частично затёртую подсказку, а не сам ключ. Лечение одно: удалить старый ключ и создать новый.

*Как понять, что получилось:* ключ вида `sk-ant-…` лежит в вашем хранилище паролей, и вы можете его оттуда достать.

### Шаг 9. Поставьте лимит расходов

Это делается **до** первого боевого запуска, а не после.

**Лимит организации:**
1. **Settings → Billing**.
2. В секции **Spend limits** нажмите **Adjust limit** (или **Set limit**, если лимита ещё нет).
3. Введите сумму.

Ваш лимит не может превышать потолок вашего тарифного «тира»: Start — $500/мес, Build — $1 000/мес, Scale — $200 000/мес, Custom — без потолка. Тир присваивается автоматически по истории использования. **Учтите:** новые организации и организации с маленькой историей стартуют в «оценочном» состоянии (Evaluation tier) с лимитами **ниже** табличных — не удивляйтесь, если доступная сумма меньше ожидаемой.

**Лимит workspace** (если вы сделали шаг 6): **Settings → Workspaces** → выберите свой workspace → вкладка **Spend limits** — месячный потолок и уведомления при достижении порогов. Рядом вкладка **Rate limits** — ограничения по частоте запросов и токенам в минуту. Лимит workspace не может быть выше лимита организации; если его не задать, workspace наследует лимит организации.

*Как понять, что получилось:* на странице Billing в секции Spend limits видна ваша сумма, а не «no limit».

Что произойдёт, когда лимит упрётся, — см. блок «Контроль расходов» ниже: поведение у своего лимита и у потолка тира **разное**, и это важно.

## Часть 2. Подключение в Power Platform

Здесь важная развилка: **сам коннектор уже создан** — я завёл его в среде командой `pac connector create` из файлов определения, он лежит в решении и называется **Anthropic-Claude-LMS-Exam**. Вам не нужно собирать его в мастере руками. Ваша часть — создать **подключение** и вставить в него ключ; ключ может ввести только человек.

Если вдруг коннектора в среде не окажется (другая среда, пересоздание) — это снова моя часть работы, не ваша: скажите, и я заведу его из тех же файлов.

### Шаг 10. Войдите под правильной учётной записью

Откройте **make.powerautomate.com** (подойдёт и **make.powerapps.com** — коннектор виден в обоих).

Войдите **под той учётной записью, которой принадлежат потоки экзамена** — по методичке это отдельная учётка с лицензией Premium, а не ваша личная. Подключение принадлежит тому, кто его создал; если создать его «от себя», потоки будут работать от вашего имени, и всё сломается в день, когда вы поменяете пароль или уйдёте в отпуск с MFA.

В правом верхнем углу **проверьте выбранную среду** — это самая частая ошибка: всё делается правильно, но в соседней среде.

*Как понять, что получилось:* в правом верхнем углу указана нужная среда, а в правом меню — нужная учётная запись.

### Шаг 11. Найдите коннектор

В левом меню найдите **Custom connectors** (в русском интерфейсе — «Настраиваемые соединители»).

Если пункта в меню нет: нажмите **More** («Ещё») → **Discover all** («Просмотреть все») → раздел **Data** («Данные») → **Custom connectors**. Этот путь подтверждён документацией, но расположение пунктов в меню Microsoft периодически меняет — ищите по названию.

В списке должен быть **Anthropic-Claude-LMS-Exam**.

*Как понять, что получилось:* коннектор виден в списке. Если его нет — вы, скорее всего, не в той среде (вернитесь к шагу 10); если среда верная, а коннектора нет — это ко мне.

### Шаг 12. Создайте подключение и введите ключ

Вариант А (из коннектора): откройте коннектор → вкладка **Test** → **New connection** (пункт называется примерно так) → в поле **Ключ API Anthropic** вставьте ключ `sk-ant-…` → **Create connection**.

Вариант Б (из общего списка подключений): левое меню → **Connections** («Подключения») → **New connection** → найдите в списке `Anthropic-Claude-LMS-Exam` → вставьте ключ → создать.

Оба варианта дают один и тот же результат. Вставляйте ключ **целиком, без пробелов по краям и без каких-либо приставок** — никакого слова `Bearer` перед ключом добавлять не нужно (в нашем коннекторе ключ уходит в заголовок `x-api-key` как есть).

*Как понять, что получилось:* в списке **Connections** появилась строка с коннектором Anthropic, статус — «Connected» / «Подключено». Сам ключ после сохранения больше не показывается — это нормально и правильно.

### Шаг 13. Подождите несколько минут перед проверкой

Это не перестраховка, а прямая рекомендация документации Microsoft: «When using an API key, we recommend against testing the connector immediately after you create it. It can take a few minutes until the connector is ready to connect to the API».

**Ошибка 401 сразу после создания подключения — чаще всего именно это, а не неверный ключ.** Подождите 5 минут и повторите, прежде чем идти перевыпускать ключ.

### Шаг 14. Проверьте смоук-тестом

Запустите поток **«Смоук: Claude»** (я его подготовлю). Он делает один крошечный вызов: модель `claude-sonnet-5`, `max_tokens` = 200, ответ по простой схеме `{"ok": true}`. Это проверка связки «коннектор + ключ + оплата», а не качества модели.

Запуск: откройте поток → **Run** («Запустить») → посмотрите историю запусков.

*Как понять, что получилось:* поток завершился успешно и в результате действия виден JSON с полем `ok`. Расход — доли цента.

Если не получилось, смотрите код ответа в истории запуска:

| Что видно | Что это значит | Что делать |
|---|---|---|
| **401** сразу после создания подключения | коннектор ещё «прогревается» | подождать 5 минут и повторить (шаг 13) |
| **401** и через 15 минут | ключ введён с ошибкой, отозван или истёк | пересоздать подключение, вставив ключ заново; если не помогло — выпустить новый ключ |
| **400**, в тексте `anthropic-workspace-id is required` | ключ создан без привязки к workspace | выпустить новый ключ, указав workspace (шаг 7) |
| **400**, в тексте «You have reached your specified API usage limits» | упёрлись в **свой** лимит расходов | поднять лимит в Settings → Billing |
| **402** | закончились кредиты | купить кредиты (шаг 5) |
| **429** | превышена частота запросов или месячный потолок | см. блок «Контроль расходов» |
| **404** с текстом про модель | опечатка в идентификаторе модели или модель недоступна организации | это ко мне |
| поток «висит» и падает примерно через 2 минуты | таймаут Power Automate (120 секунд на синхронный вызов) | это ко мне — лечится размером запроса и настройками потока |

В любом непонятном случае сохраните из истории запуска заголовок ответа **`request-id`** (вид `req_018EeWyXxfu5pfWkrYcMdjWG`) — без него поддержка Anthropic не сможет разобрать инцидент.

### Шаг 15. Политика DLP (если в тенанте она есть)

Если в вашем тенанте настроены политики предотвращения потери данных, пользовательский коннектор нужно в них разрешить — иначе потоки будут падать ещё до вызова API.

По методичке: коннектор Anthropic относится к группе **Business** вместе с Dataverse и Office 365 Outlook, а пользовательские коннекторы разрешаются по шаблону адреса **`https://api.anthropic.com/*`**.

Делается это в **Power Platform admin center** (admin.powerplatform.microsoft.com) → раздел политик (**Policies → Data policies**, пункт называется примерно так) администратором тенанта. Если политик DLP в тенанте нет — шаг пропускается.

*Как понять, что получилось:* смоук-тест из шага 14 проходит, и в истории запуска нет сообщений про запрет политикой DLP.

## Что НЕ надо делать

**1. Не путайте подписку Claude с API.**
`claude.ai` (Pro, Max, Team) и Claude Console — разные продукты с разной оплатой. Подписка на чат **не даёт** ключа API и не оплачивает вызовы из потоков. Оплата API — это кредиты в Console (шаг 5). Не пытайтесь «сэкономить», думая, что подписка уже всё покрывает: платформа просто не заработает.

**2. Не вставляйте ключ в репозиторий и в тело потока.**
Ключ живёт **только** в подключении Power Platform. Не кладите его в файл в репозитории, в настройки сайта, в переменную окружения проекта, в HTTP-действие потока «напрямую». Ключ, вписанный прямо в HTTP-действие, **виден в истории запусков** — то есть любому, кто имеет доступ к потоку. Ключа нет ни в одном файле этого проекта, и так и должно остаться.

**3. Не пересылайте ключ в переписке.**
Ни в чате, ни в почте, ни в мессенджере, ни скриншотом, ни «на минутку». В том числе **не присылайте ключ мне** — я его не запрошу и он мне не нужен: коннектор создаётся из файлов определения, ключ вводится только вами и только в форму подключения. Если ключ где-то засветился — считайте его скомпрометированным: выпустите новый, пересоздайте подключение, удалите старый ключ в Console.

**4. Не тестируйте подключение в первые минуты после создания.** См. шаг 13: 401 в это время ничего не означает, а перевыпуск ключа из-за него — лишняя работа и лишний риск.

**5. Не считайте авто-пополнение (auto-reload) лимитом расходов.** Это противоположные вещи: авто-пополнение **само тратит** деньги, докупая кредиты при падении баланса. Лимит ставится отдельно (шаг 9). Включать авто-пополнение стоит только после того, как выставлен лимит расходов.

**6. Не создавайте ключ без привязки к workspace** — получите 400 на каждом вызове (шаг 7).

**7. Не используйте личный ключ как боевой.** Личный ключ умирает вместе с выходом человека из организации. Для автоматизации — service account key.

**8. Не архивируйте workspace** «чтобы прибраться». Это необратимо и убивает все ключи внутри.

**9. Не покупайте кредиты «с запасом на два года».** Они сгорают через год и не возвращаются.

**10. Не собирайте коннектор руками в мастере**, если он уже есть в среде. Ручная сборка даёт другой коннектор с другим идентификатором — потоки его не увидят, и придётся разбираться, какой из двух настоящий.

## Контроль расходов

**Как устроена оплата.** Предоплаченные кредиты, списание только за успешные вызовы. Никаких «неожиданных счетов в конце месяца» быть не может по конструкции: закончились кредиты — вызовы перестают проходить (ошибка 402).

**Три рубежа защиты, поставьте все три:**

1. **Небольшой первый платёж.** Пополняйте на сумму, потерю которой вы спокойно переживёте. Докупить — минута.
2. **Лимит организации** (Settings → Billing → Spend limits). Верхняя граница на месяц для всей организации.
3. **Лимит workspace** (Settings → Workspaces → ваш workspace → Spend limits). Отсечённый бюджет именно под экзамен, плюс уведомления при достижении порогов. Ради этого и создавался отдельный workspace — на Default лимит поставить нельзя.

**Что произойдёт при упоре в лимит — два разных сценария, различайте их:**

| Упёрлись во что | Что вернёт API | Когда отпустит |
|---|---|---|
| **ваш собственный лимит** (тот, что вы задали) | **400**, текст начинается с «You have reached your specified API usage limits» | сразу, как только поднимете лимит |
| **потолок вашего тира** (Start $500 / Build $1 000 / Scale $200 000) | **429** без заголовка `retry-after`, в деталях `error_code = enforced_spend_limit_reached` | только **1-го числа следующего месяца в 00:00 UTC** |

Второй случай неприятен тем, что автоматические повторы бесполезны — поток будет биться в стену до начала месяца. Поэтому свой лимит лучше держать заметно ниже потолка тира: тогда вы первым делом получите «мягкую» ошибку 400, которую можно снять за минуту, а не «жёсткую» месячную блокировку.

**Где смотреть расход.** В левом меню консоли две страницы:
- **Usage** (`platform.claude.com/usage`) — графики входных и выходных токенов, сколько запросов отбито по частоте, процент кеширования. Фильтры: workspace, модель, период, конкретный ключ.
- **Cost** — дневной график расходов, общая сумма, разбивка по моделям. Фильтры: workspace, модель, месяц.

Обе страницы выгружаются в **CSV**. Доступ к ним есть у ролей Limited Developer, Developer, Billing и Admin.

Чего на этих страницах нет: **разбивки по конкретным людям**. Разложить расход по сотрудникам через интерфейс консоли нельзя (это возможно только программно и только для сценариев Claude Code). Для нас это не проблема: экзамен ходит в API под одним служебным ключом, и полезная разбивка — по workspace и по модели.

**Внутренний учёт в платформе.** Каждый вызов модели пишется в журнал `new_examlog` с токенами и расчётной стоимостью — это нужно для контроля бюджета внутри LMS. Важно понимать: **источником истины по деньгам остаётся страница Cost в консоли**, внутренняя цифра — оценочная. Отдельно замечу техническую тонкость, которую я учту при сборке потоков: наивный подсчёт «входные токены × цена» **занижает** расход в разы, потому что при кешировании подсказок основная масса входных токенов учитывается в отдельных полях (`cache_creation_input_tokens` и `cache_read_input_tokens`) и в `input_tokens` не попадает. Считать надо по всем трём полям с разными ставками — это моя часть работы, но если вы увидите расхождение между журналом LMS и страницей Cost, причина, скорее всего, здесь.

**Раз в месяц полезно сделать три вещи:** заглянуть на страницу Cost, свериться с лимитом и проверить, не подходит ли срок действия ключа.
