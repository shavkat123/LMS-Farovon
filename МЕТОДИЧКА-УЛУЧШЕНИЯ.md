## 1. Безопасность 🔴 (исправить в первую очередь)

### 1.1. CSP фактически отключён — `script-src *`

**Где:** `sitesetting.yml` → `HTTP/Content-Security-Policy: script-src * 'nonce'`

`script-src *` разрешает загрузку скриптов с **любого** домена — это сводит на нет защиту от XSS,
ради которой CSP и существует. Nonce при этом теряет смысл.

**Как исправить:** перечислить только реальные источники:

```
script-src 'self' 'nonce' https://cdn.jsdelivr.net;
```

После замены проверить H5P-плеер — он самый чувствительный к CSP (там уже есть
обработка nonce в `h5p-player`, так что должен пережить).

### 1.2. Дубль настройки `Webapi/contact/fields`, одна из которых `*`

**Где:** `sitesetting.yml` — настройка встречается **дважды**:

| ID | Значение |
|---|---|
| `685fe5f3-...` | `*` (все поля контакта!) |
| `a3b4c5d6-...` | `fullname,emailaddress1` |

Какая из них применится — лотерея, но если выиграет `*`, любой пользователь с table
permission на contact сможет читать через `/_api/contacts` **все** поля коллег:
телефоны, адреса, даты рождения и т.д.

**Как исправить:** удалить запись со значением `*`, оставить явный список полей.
Заодно прогрепать `sitesetting.yml` на другие дубли (`grep adx_name | sort | uniq -d`).

### 1.3. Экономика монет полностью на клиенте — баланс можно накрутить

**Где:** `web-templates/rewards-shop` + `table-permissions/Reward-Purchase-Self.tablepermission.yml`

Цепочка проблемы:
1. Баланс считается в Liquid: `total_earned - total_spent` — это только **отображение**.
2. Покупка делается из браузера: `POST /_api/new_rewardpurchases` с `new_pointsspent` в теле.
3. Table permission `Reward-Purchase-Self` даёт `create: true` **и `write: true`**.

Следствие: любой сотрудник может из DevTools (а) создать покупку с `new_pointsspent: 0`,
(б) отредактировать свою покупку задним числом, (в) купить при недостаточном балансе —
сервер ничего не проверяет.

**Как исправить (по нарастанию надёжности):**
- *Минимум:* в `Reward-Purchase-Self` поставить `adx_write: false` (покупки create-only).
- *Правильно:* перенести создание покупки в Power Automate flow или Dataverse-плагин,
  который сам пересчитывает баланс из `new_h5pprogress` и отклоняет покупку при нехватке.
  Клиент шлёт только `rewarditemid`, цену берёт сервер из `new_rewarditem.new_pointscost`.
- *Идеально:* завести таблицу транзакций `new_pointsledger` (начисление/списание одной
  сущностью) — баланс становится суммой по журналу, его невозможно «рассинхронизировать».

### 1.4. Power Automate Flow URL с sig-токеном зашит в HTML

**Где:** `h5p-player` (строка ~347): `FLOW_URL = 'https://...powerplatform.com/...&sig=-Rgw9F...'`

URL с подписью виден в исходнике страницы каждому посетителю. Flow принимает произвольный
`fileName` и возвращает содержимое файла из SharePoint — то есть это **публичный прокси к
вашей библиотеке SharePoint**: можно запросить любой файл, не только уроки.

**Как исправить:**
1. Внутри flow валидировать `fileName` регуляркой `^[0-9a-f-]{36}\.h5p$` — отдавать только
   файлы-уроки.
2. Сам URL вынести в Site Setting (`H5P/FlowUrl`) и подставлять через Liquid — тогда
   ротация sig не потребует правки шаблона.
3. (Опционально) добавить в flow проверку заголовка/секрета, известного только порталу.

### 1.5. Мелкие, но стоит закрыть

- `Webapi/adx_webrole/enabled` и `adx_webrole_contact/enabled` — Web API к ролям открыт.
  Если используется только в `admin-users`, ограничьте table permission ролью HR/Admin
  и перепроверьте `fields`.
- В `h5p-player` патчится `window.fetch` с `credentials: 'include'` для всех
  `*.sharepoint.com` — после перехода на flow-прокси этот код можно удалить.

## 2. Архитектура 🟠

### 2.1. Каждый шаблон — монолит «CSS + HTML + Liquid + JS» на 300–650 строк

19 шаблонов несут собственный `<style>`-блок, 19 — собственный `<script>`.
Самые крупные: `h5p-player` (638 строк), `h5p-progress-list` (608), `rewards-shop` (575),
`h5p-catalog` (548), `forum` (461), `header` (449).

Последствия: один и тот же CSS-паттерн (карточка, бейдж, кнопка «назад») копипастится
между шаблонами; правка стиля = правка в N местах; diff в git нечитаем.

**Рекомендация — целевое разделение:**

```
web-files/
  fv-theme.css      ← дизайн-токены (:root) + общие компоненты (.fv-card, .fv-badge…)
  fv-common.js      ← общий JS: apiPost с CSRF, escHtml, toast, fmtDate
web-templates/
  <шаблон>          ← только разметка + Liquid + специфичный код этой страницы
```

Подключение `fv-theme.css` и `fv-common.js` — один раз в Header / page-template.
Переносить постепенно: новый код пишем сразу в общие файлы, старые шаблоны
мигрируем по мере касания.

### 2.2. Дизайн-токены есть, но не используются

В репо лежит готовый файл токенов — `Farovon lms design/colors_and_type.css`
(цвета, шкала шрифтов, радиусы, тени). При этом в шаблонах портала всё захардкожено:
`#1E3A8A` встречается 47 раз, `#E5E7EB`, `#94A3B8`, `#0B1220` — десятки раз.

**Рекомендация:** перенести токены в `web-files/fv-theme.css`:

```css
:root {
  --fv-primary: #1E3A8A;
  --fv-primary-hover: #152D6E;
  --fv-ink: #0B1220;
  --fv-muted: #64748B;
  --fv-faint: #94A3B8;
  --fv-border: #E5E7EB;
  --fv-surface-2: #F8FAFC;
  --fv-accent-bg: #EEF2F9;
  --fv-radius: 12px;
  --fv-shadow-card: 0 1px 3px rgba(11,18,32,.05);
}
```

и в новых стилях писать `color: var(--fv-primary)`. Ребрендинг/тёмная тема тогда — правка
одного файла.

### 2.3. Дублированный JS: CSRF-токен реализован 5 раз

`getCsrfToken()` / парсинг `/_layout/tokenhtml` скопирован в `h5p-catalog`, `h5p-player`,
`h5p-progress-list`, `h5p-upload`, `rewards-shop` — пять чуть разных версий одного кода.

**Рекомендация:** одна функция в `fv-common.js`:

```js
window.FV = window.FV || {};
FV.api = async function (path, method, body) {
  const tok = await FV._getToken();          // кэшируется
  const res = await fetch('/_api/' + path, {
    method, credentials: 'include',
    headers: { 'Content-Type': 'application/json', '__RequestVerificationToken': tok },
    body: body ? JSON.stringify(body) : undefined
  });
  if (!res.ok) throw new Error(await res.text());
  return res;
};
```

### 2.5. Отладочный код в проде

В `h5p-player` — **36** вызовов `console.*`, плюс по мелочи в `h5p-upload`,
`h5p-progress-list`, `rewards-shop`.

**Рекомендация:** обернуть в флаг:

```js
var DEBUG = location.search.indexOf('debug=1') > -1;
function log() { if (DEBUG) console.log.apply(console, arguments); }
```

Диагностика остаётся доступной (`?debug=1`), консоль пользователей чистая.

### 2.6. Liquid-мелочи

- Подсчёт элементов циклом (`{% for %}{% assign count = count | plus: 1 %}{% endfor %}`)
  в `rewards-shop`, `home` — заменяется на `{{ collection.size }}` для массивов entities.
- Страницы-дубли `обратная-связь_1c4dca9d` и `обратная-связь_b2adcb21` — оставить одну,
  вторую удалить (проверив, на какую ссылаются weblink sets).
- `content-snippets/` весит ~1 МБ — там почти наверняка дефолтные сниппеты стартового
  шаблона, которые сайт не использует. Провести ревизию и вычистить.
- В `header` функция `setHeight()` навешана на `resize`, но не вызывается при загрузке —
  либо вызвать сразу, либо удалить вовсе (max-height для collapse-меню можно задать CSS).

### 2.7. Repo-гигиена

- `Farovon lms design/uploads/ТЗ ... (DRAFT).docx` — бинарный черновик в git; лучше
  хранить ТЗ в markdown (как `H5P_ТЗ_PowerPages_для_ClaudeCode.md`) или вне репо.
- Завести `docs/` и положить туда: схему таблиц Dataverse (она уже описана в memory),
  схему ролей/permissions, инструкцию деплоя (`pac paportal upload/download`).

## 3. Визуал и UX 🟡

Общая оценка: визуальный язык **уже хороший и консистентный** — slate-палитра, синий
primary `#1E3A8A`, карточки 12px радиуса, eyebrow-подписи капсом. Ниже — что докрутить.

### 3.1. Конфликт шрифтов с дизайн-системой

Дизайн-кит (`Farovon lms design/`) канонизирует **Roboto**, портал везде использует
**Inter**. Оба неплохи, но нужно выбрать один и зафиксировать в дизайн-системе.
Inter уже внедрён в 14 шаблонах — прагматичнее объявить каноном его и поправить кит.

### 3.2. Жирные начертания шрифта не загружаются

Inter подключается как `wght@400;500;600`, но в стилях **118 раз** используется
`font-weight: 700/800`. Браузер синтезирует жирность сам («faux bold») — заголовки
выглядят грязнее, чем могли бы.

**Фикс:** `...family=Inter:wght@400;500;600;700;800&display=swap`.
Заодно загружать шрифт **один раз** в Header, а не в каждом из 14 шаблонов.

### 3.3. Мёртвый UI — колокольчик уведомлений

В шапке есть кнопка-колокольчик с красным бейджем, но за ней нет функционала.
Красная точка обещает «у вас есть непрочитанное» — пользователь кликает в пустоту.
Либо скрыть до реализации уведомлений, либо повесить на неё дропдаун с последними
новостями (таблица новостей уже есть).

### 3.4. Смешанная локализация

Русские строки захардкожены («Найти урок или раздел…», «Назад к каталогу»), но fallback'и
системных сниппетов — английские (`Sign In`, `Skip to main content`), а бренд-блок —
`LEARNING HUB`. Если аудитория русскоязычная — пройтись по `default:`-веткам и заменить
resx-fallback'и на русские content snippets. Если планируется таджикский/английский —
наоборот, переносить русские строки в snippets, а не хардкодить.

### 3.5. Типографика мелких подписей

Eyebrow/метаданные набраны 9–11px капсом — на границе читаемости, особенно
`9px letter-spacing 0.12em` в логотипе. Рекомендация: минимум **10px** для caps-подписей
и проверить контраст `#94A3B8` на белом (4.0:1 — ниже WCAG AA для мелкого текста;
для подписей лучше `#64748B`).

### 3.6. Состояния интерфейса

Что проверить на каждой странице-списке (каталог, магазин, лидерборд, задания):
- **Пустое состояние** — есть ли дружелюбная заглушка («Пока нет уроков») с иконкой и CTA;
- **Состояние загрузки** — для страниц с клиентским fetch (задания, магазин) добавить
  скелетоны вместо прыжка контента;
- **Состояние ошибки** — сейчас местами `alert alert-danger` с технической строкой;
  пользователю достаточно «Не удалось загрузить. Обновите страницу», технику — в console.

### 3.7. Доступность (быстрые победы)

- Skip-link уже есть — 👍, но `#mainContent` рендерится только на странице поиска;
  добавить `id="mainContent"` в основной layout, чтобы ссылка работала везде.
- У кнопки-колокольчика и тогглера есть aria-label — 👍. Проверить остальные icon-only
  кнопки (магазин, kanban).
- Для динамически обновляемых блоков (баланс после покупки) добавить `aria-live="polite"`.

### 3.8. Консистентность компонентов

Карточка/бейдж/кнопка-назад реализованы в каждом шаблоне заново с микрорасхождениями
(радиусы 7/8/9/10/12px, паддинги на глаз). После выноса в `fv-theme.css` (п. 2.1–2.2)
зафиксировать шкалу радиусов из дизайн-кита: например 8px — контролы, 12px — карточки,
14px — hero. Это самый дешёвый способ сделать продукт «дороже» на вид.

## 4. Производительность 🟢

### 4.1. H5P: урок перекачивается целиком при каждом открытии

`h5p-player` каждый раз: качает весь `.h5p` (архив может быть десятки МБ) через Flow →
распаковывает JSZip в памяти → создаёт blob-URL'ы. Повторное открытие того же урока —
снова полная закачка.

**Рекомендация:** кэшировать архив в **Cache API / IndexedDB** с ключом
`contentId + modifiedon` (modifiedon уже доступен в FetchXML). Повторный вход в урок
станет мгновенным, нагрузка на Flow (а это платные запросы PA) упадёт в разы.

### 4.2. FetchXML без ограничений

На главной и в каталоге выбираются **все** активные `new_h5pcontent` и **весь** прогресс
пользователя без `top`/постранички. Сейчас данных мало — работает; на 200+ уроках главная
начнёт тормозить. Добавить `top` + пагинацию в каталог заранее дешевле, чем потом.

### 4.3. Загрузка ресурсов

- `bootstrap-icons` грузится с CDN в Header — нормально, но добавить
  `<link rel="preconnect" href="https://cdn.jsdelivr.net">`.
- `frame.bundle.js` (~большой) грузится только в плеере — правильно; убедиться, что
  `main.bundle.js`/`jszip` не подключены глобально.
- Hero-картинка `/Homehero.png` в инлайн-стиле — проверить вес, сжать в WebP.

## 6. Чего в проекте уже хорошо (не трогать)

- Единый визуальный язык (slate + `#1E3A8A`, карточки, eyebrow-подписи) — выглядит цельно.
- Грамотная работа с CSP-nonce и iframe-патчами в H5P-плеере — нетривиальная задача решена.
- Table permissions разделены по ролям и сценариям (Self/Mentor/Read/Write) — структура правильная,
  нужна только точечная донастройка (write на покупках).
- Документирующие комментарии в шаблонах (схема полей в шапке `rewards-shop`, ловушки
  sharepointdocumentlocation в `h5p-player`) — сохраняйте эту практику.
- Skip-link, aria-label'ы, адаптивная шапка — база доступности заложена.
